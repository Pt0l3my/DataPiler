DataPiler 0.2.41 brings together everything since 0.2.0:
- map jobs that keep what they read and pick up where they stopped;
- the game's map tiles laid out as overviews;
- a Deleted bin, so nothing collected is lost;
- every game version's data kept side by side;
- Pause and Resume;
- Pack 7z for uploads;
- updates installed from a file;
- EldenNet's derivation round as a job.

**Coming from 0.2.0: press Update…**
- 0.2.0's **Update…** button finds this release, downloads it, checks it and installs it. Your settings, workspace,
  share folder, logs, jobs and Python environment stay as they are.
- From this version on, the Update pop-up also takes a release zip you dropped on it or chose with **Add file**.

**Job cards**
- **Pause** finishes the step that is running and keeps the job's finished steps. **Resume job** goes on from the
  next step, even after DataPiler was closed.
- **Stop** asks before it cuts a job short, and **Start again** asks before it drops what was kept.
- A card can be dragged into your own order, and the order survives a restart.
- Cards fold to their title row:
  - finished jobs start folded;
  - jobs finished since DataPiler started stay open;
  - your own choice wins, and **Fold all** and **Unfold all** do what they say.
- Each card has an **About** block: the job's description, a line counted from its steps (what it reads, computes and
  writes), and the codes it cites. The step-by-step columns and the steps' lines of a finished job are under
  **Details**. A running or failed step always stays in view.
- **Open folder** opens a job's workspace folder.
- **Pack 7z** packs a finished job's share file and workspace into a 7z archive, ready to upload. An archive larger
  than 29.9 MB is split into parts that 7-Zip opens from the first, and nothing about the PC goes into it.

**Nothing collected is lost**
- The new **Deleted** tab is a bin. Removing a job, a share file, a workspace file, an import or a map job's saved
  progress moves it there. **Restore** puts it back exactly, and refuses rather than overwrite.
- Removing collected data asks for `DELETE` to be typed. Only **Erase…** and **Empty bin…** erase for good.

**Game updates**
- Every completed run keeps what it read for its game version, side by side, never removed.
- A job whose last run was on another version says so, and **Update data** reads again and shows what was added,
  changed and removed. **Compare versions…** compares any two versions a job kept.

**Maps**
- Map jobs load one map at a time and keep each map's reads as soon as it loads. A crash or a stuck Smithbox costs
  only the map in hand, and **Resume job** picks up from there.
- A map that does not load in time is skipped, tried again at the end, and named in the log.
- With **Map jobs on Smithbox's OpenGL build only** (on by default), a map job waits for that build, which loads
  maps without preparing graphics. Before a map job, DataPiler reads whether Smithbox's model rendering is off.
- The map tiles you export from Smithbox are found anywhere in DataPiler's folder:
  - `make_map_overview` lays them out on their grid, as one PNG, on your PC only;
  - `check_map_tiles` measures every level against the next;
  - from the game's own mask files, overviews draw each level as the game does.
- `unpack_game_file` opens a game file that Smithbox unpacked, into the job's workspace, never shared. It uses the
  game's own Oodle library from the game's folder and never copies it.

**Reading more of the game**
- `check_fields` checks a table's fields and their types before a job reads them. A job may then read a field
  DataPiler does not list yet.
- More tables can be read:
  - the map tables, shareable for research under the `map_coords` label;
  - the map-information images' colour keys;
  - the weapon and armour rows.
- New text sets: the weapon and armour names, checked against your own data each time.
- New picks: `unused_names` (a text set's entries that no row names), each name's layer (base game or which DLC), and
  `"slots": "boss"`.

**Smithbox's server link**
- The top bar's chip says whether the link is connected, waiting for Smithbox, or getting no answer, and the Status
  card says the same.
- **Link to Smithbox's server by itself** (Settings, off at first) switches the link on once Smithbox's server answers
  and the game is closed.

**This PC**
- Tile checks and overviews use the PC's cores, and Windows' own PNG decoder once it decodes test images exactly as
  DataPiler does. Results are the same, only faster.
- Settings has **Cores for image steps** and **Memory for image steps**. Status has a **This PC** card.

**EldenNet's derivation round**
- A job step, `probe_exe`, runs EldenNet's devkit tool on the game's executable with the game closed, then the tool's
  own check of its report. It waits while the game runs and stops the tool if the game starts.
- Its report becomes the job's share file once the guard passes it: numbers, flags and fixed words only.
- **EldenNet devkit folder** (Settings): where you unpacked EldenNet's devkit package. DataPiler never bundles the tool,
  and checks it against the package's `SHA256SUMS` before each run.
- Job en-0044 runs it and leaves the report ready for Pack 7z.

**Smaller things**
- The Imported tab lists what the text database holds, by language and layer, and **Remove** takes an import out.
- The game's `[ERROR]` placeholder texts are no longer imported.
- The top bar shows the full version.
- Quit closes the window and its browser tab.
- DataPiler.exe has an icon of its own: a crimson katana in a rising slash.

**Not tried on a real PC yet**
- The update from 0.2.0 to this release through the **Update…** button: every version in between came as a test
  build, so this is the button's first real update.
